F0 · 课前闲聊

Agent 的经验，从哪里来？

读完这一章，试着解释“越用越好用”背后的数据循环。

01
这一章的核心

课程以 OpenClaw 为例：把偏好、规则和经验保存下来，在下一次任务中重新读取，Agent 才有机会持续利用过去的经验。

先分清两件事

模型本身的学习训练过程改变模型参数
本章讨论的经验积累保存外部数据，再放入上下文

把笔记写进文件，不意味着模型权重发生变化。文件里的信息需要被正确读取和使用，才会影响后续回答。

一个“记住偏好”的小例子

示例 · 周报助手

第一次，你说：“周报先写结论，再列风险，不要超过三段。”

助手把这条要求保存为规则。下一次写周报时，先读取规则，再组织内容。你修改了偏好，也要更新旧规则。

01 / 读取取出相关数据偏好、文档、历史经验
02 / 执行完成当前任务结合新问题和旧经验
03 / 提炼记录有效经验规则、纠错、重要变化
04 / 复用下次检索使用检查是否仍适用

课程里的 7 类工作区数据

文件 / 位置回答什么问题容易理解的例子
SOUL.md助手是什么角色？沟通风格、行为边界
USER.md用户有什么偏好？希望回答先给结论
AGENTS.md做事要遵守什么规则？踩坑记录、检查步骤
TOOLS.md工具与环境是什么？工具用法、环境备忘
SKILL.md某类任务怎么做？周报格式与质量标准
memory/*.md最近发生过什么？当天任务的关键事实
MEMORY.md哪些内容值得长期保留？从日常记录中提炼的稳定信息

这些是课程案例中的文件组织方式，不是所有 Agent 都必须采用的统一标准。

为什么不能只管“存得多”？

写入质量

误会、过期规则和未经确认的推断也可能被保存。需要审查、纠正和更新。

召回质量

存了不等于用到了。信息越来越多时，要找到当前相关的内容，避免全部挤进上下文。

停下来想一想

为什么“我上次说过”不保证助手这次记得？

上次的信息可能没有持久保存，也可能保存了却没有被召回，或者没有放进本次上下文。先检查这条数据链路，才能判断问题在哪里。

F1 · 大模型的本质与边界

回答很流畅，为什么还会错？

识别三类常见局限，并理解 Token 与上下文窗口。

02
这一章的核心

语言流畅不等于事实可靠。课程提醒我们：除了模型能力，还要检查它是否拿到了正确、及时、与任务相关的数据。

大模型是怎样生成文字的？

可以先把它理解为：根据已经看到的上下文，预测接下来可能出现的 Token，并一步步生成内容。它学到的语言和知识规律很强，但生成过程并不自动完成事实核验。

示例 · “天空是……”

模型可以根据常见表达续写“蓝色的”。但要回答“此刻窗外的天空是什么颜色”，还需要当前地点和实际天气等信息。

三个局限，三种数据检查

01 / 幻觉

听起来合理，事实却不对

例如编出不存在的文献。检查有没有可靠来源、是否检索正确、回答是否忠于证据。

02 / 知识截止

没有自动获得最新信息

例如把旧产品规则当成最新政策。检查来源日期，必要时接入实时数据。

03 / 个性化盲区

不了解你的具体背景

例如建议听起来正确，却不适合你的项目。补充实际目标、约束和业务资料。

阅读时保留一个边界：课程强调“补数据”的价值；这不意味着所有错误都只由缺数据造成。模型理解、推理、检索和提示方式也需要分别验证。

两个必知词：Token 与上下文

Token：处理文本的单位

文字会被切成小片段交给模型处理。一个 Token 不固定等于一个汉字或一个单词，具体取决于分词器。

API 用量通常区分输入 Token 和输出 Token。

上下文窗口：这次能看到多少

模型一次处理的内容有长度上限，历史消息、工具结果和参考资料都可能占用空间；具体限制取决于模型。

窗口很大，也不等于所有内容都能被有效利用。

类比 · 桌面与档案柜

上下文像桌面：放着当前任务要用的材料。长期记忆像档案柜：保存更多资料，需要的时候再找出来放到桌面上。桌面变大，不会自动替你整理档案柜。

遇到“AI 不好用”，先问这三句

  1. 它缺少的是事实、实时信息，还是任务背景？
  2. 资料已经存在吗？存在的话，为什么没有拿到或用对？
  3. 补上可靠资料后，能否通过可核验的问题检验改善？
有了 RAG，就不会产生幻觉了吗？

不能这样保证。检索可能拿错资料，资料可能过时，模型也可能误读。仍然需要检查来源、引用与答案之间的对应关系。

聊天产品能记住我，是否说明模型天然有永久记忆？

产品可以在模型之外保存历史和用户信息，并在后续调用中提供给模型。要区分“产品提供记忆功能”和“单次模型调用本身保存记忆”。

F2 · AI Agent 全景图

从“回答问题”到“执行任务”

把 RAG、Memory、Skill、MCP 放到同一张能力地图里。

03
这一章的核心

Agent 把模型推理、规划、记忆与工具调用组织起来。它可以查看行动结果，再决定接下来做什么。

一个任务，怎样一步步完成？

情景示意 · 分析销售增长

用户：“帮我看看上个月销售额增长了多少，以及可能的原因。”

01 / 推理确定需要什么需要两个月销售额
02 / 行动调用查询工具获取允许访问的数据
03 / 观察检查查询结果增长明显，但原因还未知
04 / 继续查活动并分析补充证据，再给结论

ReAct 把推理（Reasoning）与行动（Acting）交替组织起来。显式工作流则预先规定节点和条件。两种方式都要考虑何时结束、出错如何处理。

看见同期有促销，不等于已经证明增长由促销导致。回答应区分已知事实、推断和仍缺的证据。

四类能力，用同一个客服例子区分

RAG 查资料

先检索相关知识，再将证据交给模型回答。

客服例子：从当前版本的退货政策中，查到申请期限。

关键问题：资料是否完整、最新、可检索？

Memory 记住与召回

保存有用的事实、偏好和经历，并在需要时取出。

客服例子：记住用户此前已提供订单信息，避免重复询问。

关键问题：记什么、保存多久、何时更新？

Skill 按方法办事

把某类任务的步骤、规则与示例整理为可复用方法。

客服例子：先核验条件、再说明政策、最后给出操作步骤。

关键问题：方法是否清楚，是否适合当前任务？

MCP 标准化接入

让客户端与服务端按共同协议连接工具、资源和提示模板。

客服例子：通过标准接口接入订单查询工具。

关键问题：接入什么能力，允许访问什么？

Naive RAG 与 Agentic RAG

固定检索流程

检索一次，整理上下文，生成答案。流程简单、容易理解。

可以调整的检索流程

判断查哪里、是否补查、是否换关键词。更灵活，也增加了调用次数和控制难度。

先用任务需求决定复杂度。更多步骤不自动意味着更好的结果，还要比较正确性、耗时与成本。

给“记忆”再分一分工

类别容易理解的含义例子
工作记忆当前任务正在使用的状态和材料本次对话与刚查到的结果
语义记忆事实和稳定偏好用户喜欢先看简短结论
情景记忆具体经历上次用什么办法解决了问题
程序性记忆做事的方法与规则处理投诉的步骤

术语辨析：仓库 F2 正文将“工作记忆 / 程序性记忆”并列写在一项中。学习时把“当前状态”与“操作方法”分开理解，有助于避免混淆；这张表是导读整理，不是原文逐字摘录。

数据层为什么重要？

向量检索用于找语义相近的内容，全文检索用于找精确词项，关系查询用于按字段和条件筛选。课程后续会使用 seekdb 介绍统一数据层。
